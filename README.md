# Аудит скрытых потерь прибыли

Сервис для предпринимателя: он заполняет короткую форму (ниша, способ учёта клиентов, заявки, средний чек, маржа), а сервис считает, сколько прибыли теряется из-за ручного учёта, и выдаёт аудит с решением.

Работает полностью бесплатно: без ИИ, без серверов и без платных ключей.

Стек: Next.js (статичная сборка), TypeScript, Tailwind CSS, Supabase (необязательно), GitHub Pages.

## Как это работает

- **Расчёт** (`lib/calc.ts`) считает три точки потерь по коэффициентам ниши и способа учёта (`lib/model.ts`): заявки без ответа, недополученные повторные продажи и утечку, свою для каждой ниши.
- **Текст аудита** (`lib/report.ts`) собирается из шаблонов (`lib/templates.ts`) по структуре из `docs/prompt.md`. Для каждой из 9 ниш и 6 способов учёта есть несколько формулировок каждого блока, а наблюдения подбираются по цифрам клиента (конверсия, маржа, база, поток заявок, средний чек). Вариант выбирается по данным клиента, поэтому одинаковые данные всегда дают одинаковый текст.
- **Supabase** сохраняет каждый аудит прямо из браузера, если заданы ключи. Анонимные пользователи могут только добавлять записи, но не читать их.

Чтобы добавить формулировки, допишите варианты в массивы `lib/templates.ts`.

## Деплой на GitHub Pages

1. **Settings → Pages → Build and deployment → Source: GitHub Actions.**
2. **Actions → Deploy → Run workflow.** Дальше сайт обновляется сам после каждого пуша в `main`.

Сайт откроется по адресу `https://<ваш-логин>.github.io/profit-audit/`.

## Сохранение аудитов в Supabase (необязательно)

1. В проекте Supabase откройте **SQL Editor** и выполните по очереди `supabase/migrations/0001_audits.sql` и `0002_anon_insert.sql`.
2. В **Project Settings → API** возьмите Project URL и публичный ключ (`anon` или `publishable`).
3. В GitHub: **Settings → Secrets and variables → Actions** добавьте секреты `SUPABASE_URL` и `SUPABASE_ANON_KEY`.
4. Перезапустите workflow **Deploy**.

Сохранённые аудиты видны в **Table Editor → audits**.

## Локальная разработка

```bash
npm install
cp .env.example .env.local   # необязательно
npm run dev
```

## Коэффициенты

Все коэффициенты в `lib/model.ts` являются отраслевыми допущениями, а не измерениями. Они намеренно консервативны: аудит должен показывать реальный масштаб, а не пугать.
