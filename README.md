# Аудит скрытых потерь прибыли

Сервис для предпринимателя: он заполняет короткую форму (ниша, способ учёта клиентов, заявки, средний чек, маржа), а сервис считает, сколько прибыли теряется из-за ручного учёта, и генерирует честный аудит с решением.

Стек: Next.js (App Router), TypeScript, Tailwind CSS, Supabase, Claude API.

## Как это работает

1. **Форма** (`components/AuditForm.tsx`) отправляет данные в `POST /api/audit`.
2. **Расчёт** (`lib/calc.ts`) считает три точки потерь по коэффициентам ниши и способа учёта (`lib/model.ts`):
   - заявки без ответа или без продолжения;
   - недополученные повторные продажи по базе;
   - процессная утечка, своя для каждой ниши (запчасти в автосервисе, брошенные корзины в e-commerce, неявки в услугах и т.д.).
3. **Аудит** генерирует Claude по промпту из `lib/prompt.ts`. Модель получает только цифры расчёта и не придумывает свои.
4. **Supabase** хранит каждый аудит: входные данные, расчёт и текст (`supabase/migrations/0001_audits.sql`).

Ответ API стримится: первая строка содержит JSON с расчётом, дальше идёт текст аудита в Markdown.

## Запуск

```bash
npm install
cp .env.example .env.local   # заполните ключи
npm run dev
```

Откройте http://localhost:3000.

### Переменные окружения

| Переменная | Зачем |
|---|---|
| `ANTHROPIC_API_KEY` | Генерация аудита |
| `SUPABASE_URL` | Сохранение аудитов (необязательно) |
| `SUPABASE_SERVICE_ROLE_KEY` | Серверный доступ к таблице `audits` (необязательно) |

Без переменных Supabase сервис работает, но аудиты не сохраняются.

### База данных

Выполните `supabase/migrations/0001_audits.sql` в SQL Editor проекта Supabase или через `supabase db push`.

## Коэффициенты

Все коэффициенты в `lib/model.ts` являются отраслевыми допущениями, а не измерениями. Они намеренно консервативны: аудит должен показывать реальный масштаб, а не пугать. Уточняйте их по мере накопления реальных аудитов.
